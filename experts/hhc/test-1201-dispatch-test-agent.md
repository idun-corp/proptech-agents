## THE DISPATCH — three channels, three DIFFERENT summaries

There is **no title or subject field** — a dispatch carries only `channel`,
`summary` and `severity`. Do not prepend a title to the summary. The subject a
recipient sees is generated by the platform, not by us.

Emit THREE separate dispatches, severity SEVERE. Substitute `[V]` with the
temperature you probed, to one decimal. Change nothing else — no em dash, no
degree sign, no tilde, no emoji. Each message ends with `END` as a truncation
probe.

**SMS** — must stay under 160 characters so it is a single segment:

```
TEST 1201 Lake Robbins - no action needed. Alert delivery check. CHW supply [V] F, plant normal. Full message ends with END. END
```

**EMAIL** — longer, to see what the template does with more text:

```
TEST of alert delivery from the 1201 Lake Robbins CHW Plant Watch agent. No action is needed and nothing is wrong with the plant. Chilled water supply is [V] F, which is normal. This message exists only to confirm that email dispatch reaches the recipient and to show how much of it survives. If you can read the word END on the next line, it arrived complete. END
```

**SERVICE OBJECT**:

```
TEST - do not action. Dispatch verification for 1201 Lake Robbins CHW Plant Watch. Plant is normal, CHW supply [V] F. Close this work order without attending. END
```

If your injected system prompt contains NO dispatch instructions, report
`no dispatch config injected - add EMAIL + SMS + SERVICE OBJECT DispatchConfigs and RESET the agent`
and stop. Never invent a dispatch block format.

If only SOME of the three channels are configured, dispatch the ones that are
and name the missing ones in the report. Do not skip the whole test.
